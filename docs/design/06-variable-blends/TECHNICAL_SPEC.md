### 2.2 Data flow

```
CLI / UI ──execute──> fillet_edge {id, edges[law], profile, corners}
   core: resolve edges / vertices by name | point (SC-N1) → validate laws (geometry/blend/law.ts) → expression → samples
         → recipe { op:'fillet', source, edges, radii, profile?, corners? } → ctx.kernel.evaluate(recipe)
   native: MakeFillet (circular, rails) → [profile ≠ circular] replace blend faces keeping rails → [setback] trim + N-sided fill
           → BRepCheck → named shape | null + BlendReport
   core: null → ctx.kernel.blendReport(recipe) → BLD_* code + ids + remediation (probe hint) ; ok → mesh entity { brep: recipe }
check_blends → ctx.kernel.faceQuery.blendInfo(shape) + edgeContinuity(contact edges) → data { blends[], findings[] }
```

### 2.3 Laws check

- L1/L5: every capability is a registered command; `probe_fillet` and `check_blends` are queries (`readOnly`, `data`).
- L3: commands return a new document; laws stored as given (expressions as text, not as sampled arrays).
- L8: params are design intent (radii, fractions, rho, shape factor, setback lengths, expressions, face / edge / vertex names and
  points). Sampling of an expression law happens at evaluation, deterministically (fixed `samples`, uniform `t`).
- L9: all construction through `ctx.kernel`; `requiresKernel: true` on the four mutating commands; Manifold refuses.
- L2: `geometry/blend/*` is pure math (no DOM, no fetch); native code lives in `solver/`.
- No tension found that needs the owner (W6).

## 5. Kernel / algorithms

### 5.1 Radius laws (core `geometry/blend/law.ts`, native `blends.cxx`)

| Law                    | Core validation                                                                                                         | Native construction                                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- | ------------------------------------------------ |
| constant               | `size > 0`                                                                                                              | `Add(r, E)`                                                                                                                    |
| start → end            | both > 0                                                                                                                | `Add(r1, r2, E)`                                                                                                               |
| control points, smooth | `t` strictly increasing in (0, 1), sizes > 0                                                                            | `Add(UandR, E)` (today)                                                                                                        |
| control points, linear | same                                                                                                                    | `Add(Law_Composite of Law_Linear pieces, E)`                                                                                   |
| expression             | parses with `lib/expression.ts` (variable `t` only + document parameters), finite > 0 at every sample, `samples` 5..257 | sampled at `t_k = k/(n-1)` → `UandR`                                                                                           |
| closed chain           | `                                                                                                                       | r(0) − r(1)                                                                                                                    | ≤ 1e-9 × size`else`BLD_LAW_NOT_PERIODIC` | periodic interpolation (`Law_Interpol` periodic) |
| `over: 'chain'`        | —                                                                                                                       | `t` is the relative abscissa on the contour (OCCT `RelativeAbscissa`); `over: 'edge'` maps a per-edge `t` into the chain range |

Geometric facts used by the VCs (derived in `validation/generate_blend_refs.mjs`): on two planes meeting at interior angle α the
contact lines lie at `t = r cot(α/2)` from the edge — for **both** the section construction and the rolling-ball envelope (the
sphere of radius r centred r from a plane touches it at the foot point, which satisfies the characteristic condition), so planar
face areas are construction-independent; the removed volume is `∫ A(r(s)) ds` with `A(r) = r²[cot(α/2) − (π − α)/2]` for the
section construction. For a linear law of slope 0.05 the envelope removes 0.08 % less at mid-span, for slope 0.1 the total removed
differs by 0.33 % (`data/variable_radius_laws.json`, `data/extra_cases.json`); VC-BLD-30 tells which one the kernel builds.

### 5.2 Chord on curved faces (core + native)

Planar pair: closed form (today). Curved pair: per sample `s` the native code intersects the section plane (normal to the edge) with
both faces, takes the tangent lines at the edge point, computes the local wedge angle `α(s)` and `r(s) = c(s) / (2 cos(α(s)/2))`,
then builds a law (`UandR`, ≥ 17 samples) — exact for a cylinder rim against its cap (meridian sections are two perpendicular
lines: VC-BLD-06). Refuse with `BLD_CHORD_UNDEFINED` where `α(s) ∉ (0, π)` (tangent faces).

### 5.3 Profiles: section curves

In the section plane at spine point `s`: contact points `A` (on face 1), `B` (on face 2), unit tangents `u1`, `u2` of the face
sections pointing **towards** the corner, their intersection `T` (planar faces: the edge point).

| Profile            | Section                                                                                                                                                                                                                                                         | Continuity                         | Closed-form checks                                                                                                                                                                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | ------------------------------ | ----- | ---------------------- | -------------------------------- | -------------------------------------------------------------------------------------- |
| circular           | arc tangent at A, B                                                                                                                                                                                                                                             | G1 (curvature jump 1/r: VC-BLD-10) | `A(r)` above                                                                                                                                                                                                                                                                                                |

Sizing of non-circular profiles by `radius`: the contact lines are those of the circular fillet of that radius (tangent distance
`r cot(α/2)`), so rails, topology and corner extents are identical to the circular case.

### 5.4 Profile replacement (native `blend_profile.cxx`) — "keep the rails, change the section"

1. Build the circular fillet with `BRepFilletAPI_MakeFillet` (same laws) → result shape, `NewFaces(I)` per contour, contact edges
   (shared edges between blend faces and support faces), spine = the input edge chain.
2. For each blend face: sample `s` along the spine (adaptive, ≥ 33 sections, chord tolerance 1e-4 × r), compute section curves
   (§5.3) from the support faces' local geometry (`BRepLProp_SLProps` at the contact points), build a B-spline surface through the
   sections (`GeomFill_Generator`-style skinning with rails as `u = 0, 1` iso-curves forced to the existing contact edges'
   3D curves; tolerance 1e-6 × bbox, max degree 8) — the Hartmann-style G^n blend on rolling-ball contact curves (R14).
3. Replace the face's surface, keeping its edges (`BRepBuilderAPI_MakeFace(surface, wire of the old edges)` + `ShapeFix_Face`),
   substitute with `BRepTools_ReShape`; corner patches touching replaced faces are rebuilt by `BRepOffsetAPI_MakeFilling` (G1 to
   all neighbours; G2 COULD).
4. `BRepCheck_Analyzer`; names: the replaced face keeps `blend(<edge>)`, corner patches keep `blend(v:…)` (naming.hxx roles).
5. Failure ⇒ `BLD_PROFILE_FAILED` with the face and section index.

### 5.5 Setback corners (native `blend_corner.cxx`)

1. Build the circular / profiled fillets with **no** corner patches at the setback vertices: trim each incident blend face at the
   section plane through the point at distance `s_i` from the vertex along edge `i` (`BRepAlgoAPI_Splitter` with a plane tool;
   remove the vertex-side piece and OCCT's corner patch).
2. The hole is bounded by the trimmed blend edges and the support face edges between the setback sections; fill it with
   `BRepOffsetAPI_MakeFilling` (boundary edges G1 to their faces, `Degree 3`, `NbPtsOnCur 15`, `NbIter 2`, `Tol3d 1e-4`,
   `TolAng 0.01`), sew (`BRepBuilderAPI_Sewing`, 1e-6 × bbox) and solidify.
3. A vertex of ≥ 4 blended edges: same path (OCCT's own patch is never attempted there).
4. Checks: `s_i ≥ t_i` (tangent distance of edge `i` at the vertex) else `BLD_SETBACK_TOO_SHORT`; fill G1 achieved ≤ 0.01 rad
   (reported) else `BLD_CORNER_FAILED`.
5. VC invariants: an edge's cylindrical blend face spans `L − s_start − s_end` (VC-BLD-12).

### 5.6 Face-face fillets, hold lines, full round (native `blends.cxx`)

| Feature                   | Algorithm                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Notes                                                                       |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `fillet_faces` constant r | offset face sets A, B by r towards the material (`BRepOffsetAPI_MakeOffsetShape` per face / `Geom_OffsetSurface`), intersect → spine (`BRepAlgoAPI_Section`), project spine on A and B → rails (`GeomAPI_ProjectPointOnSurf` sampled + `GeomAPI_PointsToBSpline`), surface `GeomFill_Pipe(spine, railA, railB, r)` (R1); split A and B along the rails (`BRepFeat_SplitShape` / `BRepAlgoAPI_Splitter`), remove the faces between the rails (consumed), sew, solidify | two faces only ⇒ `FilletSurf_Builder` is an alternative section engine (R1) |
| variable r / width        | sections built per spine sample (§5.3) instead of `GeomFill_Pipe`                                                                                                                                                                                                                                                                                                                                                                                                     | as §5.4 step 2                                                              |
| no solution               | offset surfaces do not intersect, or the blend leaves the material (planar check: `r (√2 − 1) ≥ c/√2` across a chamfer of leg c, `data/face_fillets.json`)                                                                                                                                                                                                                                                                                                            | `BLD_FACE_FILLET_NO_SOLUTION` + minimum radius when known                   |
| hold line                 | planar faces at constant wedge α: core converts the hold curve's distance `h(s)` to the edge into `r(s) = h(s) tan(α/2)` and calls the edge path (exact, VC-BLD-17); otherwise native: rail A = the hold curve, rail B from the section circle tangent to face A at the hold point and to face B                                                                                                                                                                      |                                                                             |

### 5.7 Chamfer variants (native)

`Add(D1, D2, E, F)` with `F` = face `side1`; `AddDA(D, Angle, E, F)` with the angle in radians on `F`. Distance-angle second leg on a
wedge α: `d2 = d sin φ / sin(π − α − φ)` (VC-BLD-18: 90°, d 1, 30° ⇒ 0.577350). Variable chamfer (COULD): no OCCT law ⇒ section
construction like §5.4 with a straight section.

### 5.8 Diagnostics (native → core)

After a failed `Build`: for each contour `StripeStatus(IC)`, `NbFaultyContours`, `FaultyVertex`, `HasResult`; before `Build`: vertex
valence of contour ends (≥ 4 ⇒ unsupported). The worker keeps the report of the last failed evaluation per `recipeKey`
(`blendReport(recipe)`), so core can explain a null without a second build. Core maps it (§7.1) and, for `BLD_RADIUS_TOO_LARGE`,
runs at most 8 extra evaluations to put the largest working radius in the remediation (same bisection as `probe_fillet`, cached).

### 5.9 Native queries needed by `check_blends`

Implement the null answers in `bins/llull-kernel/src/queries.rs`: `faceQuery.edgeSamples` (points, tangents along an edge) and
`faceQuery.edgeContinuity` (per sample: G0 gap, G1 angle between the two faces' normals, normal curvatures of both faces across
the edge — `BRepLProp_SLProps` on each face at the edge point's `(u, v)`, curvature in the direction normal to the edge in the
tangent plane), plus `faceQuery.blendInfo` (blend faces by name role `blend(…)`, contact edges, section circle fit at `t`:
three points of the iso-curve across the face → radius; for non-circular profiles the curvature at the section midpoint is reported
as `midCurvature` instead of a radius).
