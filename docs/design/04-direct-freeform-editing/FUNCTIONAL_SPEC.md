# DIR — Direct and freeform editing (drag, cage, poles, faces) — Functional specification

Gap id: **DIR** · Folder: `docs/design/04-direct-freeform-editing/` · Status: specification (2026-10-22), partly built (see §1) ·
Track: "design anything" freeform design (owner request 2026-10-22) · Companion: [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md) ·
Validation: [validation/README.md](validation/README.md) · Neighbours: **01 DEF** (whole-body deformations; shares the falloff

---

## 1. Summary

Designers shape freeform parts by **pulling on them**: they grab a vertex, an edge loop or a face of a subdivision cage and drag it
with a gizmo, nudge NURBS control points, crease an edge, extrude a face to grow a handle, cut a new edge loop for detail, or push
a face of a solid until it lines up with something. Fusion's Form workspace (Edit Form), Rhino SubD + Gumball, Blender edit mode,
Plasticity, NX Realize Shape and Onshape / Creo direct editing all work this way (§2). It is the fastest way to reach a shape that
no sketch describes.

This pack is the one place in the "design anything" track where **the desktop UI is the primary surface**. The PRIME DIRECTIVE
still holds without exception: every gesture previews locally (a pure dry run, nothing written) and **commits exactly one
registered command on release**; that command is the CLI tool an agent calls with the same params, so a drag and a CLI call
produce the same document and the same undo step.

What llull has today (TECHNICAL_SPEC §1):

So the gap is mostly **interaction** (sub-element selection, gizmo sessions that end in one command, cage / net overlays, fast
previews) plus the **commands those gestures need** (cage topology tools, semi-sharp creases, symmetry, surface pole edits,
general face moves, SubD → NURBS conversion) and the **numeric checks** an agent needs to verify the same edits without a screen.

### 2.3 Value

- **Shapes no sketch describes.** Handles, grips, saddles, housings, fairings, toys, consumer products: an organic cage edited by
  hand, then converted to exact NURBS / B-rep for STEP and machining (Rhino / Fusion workflow), all local and offline.
- **Agent and human on one model.** The owner drags in the desktop app while the agent watches (`--app`); the agent then makes the
  same edit precisely from the CLI ("move the top loop 3 mm up, mirrored, soft radius 10 mm"). Both are the same command.
- **Imported parts become editable.** Move / offset / delete faces on a STEP import with no history (Onshape and Creo rationale [R18]
  [R19]).
- **Fewer surprises.** Numeric checks (limit points, extraordinary-vertex list, symmetry deviation, mesh-vs-limit volume gap)
  replace "looks right".

### 4.2 Out of scope

- **T-splines** (T-junctions in the control net). The core patent US 7,274,364 is listed "Expired - Lifetime" with an anticipated
  expiration of 2024-03-26 [R27], so licensing is no longer the blocker, but Catmull-Clark SubD (Rhino's choice [R6]) covers the
  same designs; revisit only if an owner needs T-spline import.
- Mesh sculpting brushes (grab / inflate / smooth on dense meshes), mesh → SubD and quad remeshing: **07 MSH**.
- Whole-body space deformations (twist, bend, FFD lattice, deform by point on a solid): **01 DEF**. DIR edits control structures
  (cages, poles, faces); DEF maps space. Both use the falloff curves of FR-DIR-07 (one shared definition).
- Loop and other subdivision schemes, non-manifold cages (OpenSubdiv supports them [R20]; llull keeps 2-manifold cages).
- VR / pen-pressure input.

## 6. Workflows

### 6.1 Desktop UI (primary for this pack)

1. Select a subdivision solid, press **Tab** (or the "Edit cage" chip): the cage overlay appears, selection mode = Face.
2. Click a face; double-click an adjacent face for the face loop; the gizmo appears at the selection centroid, oriented to the
   average normal (FR-DIR-04).
3. Drag the normal arrow: the smooth surface ghost follows every frame (preview, FR-DIR-02, 06); the wheel changes the soft
   radius (circle drawn); type `5` + Enter for an exact 5 mm. Release → one `edit_subdivision_cage` dispatch; status bar shows
   its summary and "Copy as CLI".
4. **Alt-drag** the same arrow: extrude instead (`extrude_cage_faces`), then **I** for inset, **Ctrl-R** loop cut, **Shift-E**
   crease sharpness by dragging (each one command).
5. Turn on **X symmetry** in the cage toolbar (stored on the entity via a command); later edits mirror automatically.
6. Undo / redo step one gesture at a time. Esc during a drag cancels with nothing dispatched.
7. "Convert to NURBS" → `subdivision_to_nurbs` dialog (packed / unpacked, G0 / G1, sheets / solid) with a preview and the
   deviation figure before commit.

NURBS entities work the same way in Pole mode (net overlay, U / V falloff). B-rep solids in Face mode offer Push / Pull, Move face
(translate / rotate / offset), Delete face, each previewed through the backend kernel (TECHNICAL_SPEC §7) and committed once.

### 6.2 CLI (operator agent; same commands)

```bash
llull search cage extrude crease symmetry      # finds the DIR commands
llull add_subdivision_solid '{"box":{"size":[40,20,10],"segments":[4,2,1]},"id":"grip"}' --doc g.llull.json
llull select_cage_elements '{"id":"grip","faces":{"normal":[0,0,1],"within":0.2}}' --doc g.llull.json --json   # -> data.faces ids
llull extrude_cage_faces '{"id":"grip","faces":["f-1.5","f-1.6"],"distance":8}' --doc g.llull.json
llull edit_subdivision_cage '{"id":"grip","faces":["f-2.1"],"translate":[0,0,3],"falloff":{"radius":12,"shape":"smooth"},"symmetry":"keep"}' --doc g.llull.json
llull set_cage_symmetry '{"id":"grip","planes":["x"]}' --doc g.llull.json
llull set_cage_crease '{"id":"grip","edges":{"loopFrom":"e-2.3"},"sharpness":2}' --doc g.llull.json
llull check_subdivision id=grip --doc g.llull.json --json              # pass / warn / fail, EVs, symmetry deviation, mesh-vs-limit gap
llull render_view view=iso isolate=grip overlay=cage --doc g.llull.json --save grip.png
llull subdivision_to_nurbs '{"id":"grip","output":"solid","faces":"packed","extraordinary":"G1"}' --doc g.llull.json --kernel occt --json
llull export_step_ap242 --doc g.llull.json --kernel occt --save grip.step
```

With `--app` the same calls drive the open window and the designer sees each step; the designer's own drags show up in the
history the agent reads (`describe_scene`, feature steps). A plan (`validation/plans/target_grip_cage_tools.json`) holds the whole
job; `llull run plan.json --validate` checks element ids before any geometry work.

### 6.3 Review

There is no approval act in this pack. The UI is both the editing surface and where the owner looks at the result; the agent's
proof is numeric (`check_subdivision`, `evaluate_subdivision`, `check_surface_quality` after conversion, `mass_properties`).

## 8. Standards & regulatory alignment

| Topic              | Alignment                                                                                                                                                                                                                    |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Subdivision scheme | Catmull-Clark with OpenSubdiv rules (smooth, crease, corner masks; semi-sharp decrement by 1 per level; fractional blend; Chaikin option; boundary interpolation) so files match Blender / OpenSubdiv behaviour [R20] [R21]. |
| Exact evaluation   | Limit position / tangent masks of OpenSubdiv `catmarkScheme.h`; eigen-analysis basis of Stam 1998 for arbitrary (u, v) [R21] [R23].                                                                                          |
| SubD → NURBS       | Bicubic B-spline equals the limit surface on the regular part (Stam [R23]); EV neighbourhoods approximated (Loop & Schaefer ACC [R24], Peters PCCM [R25]); options modelled on Rhino ToNURBS [R5].                           |
| Exchange           | Converted surfaces go out through existing STEP (`export_step_ap242`) as B-spline faces; SubD cages persist in the llull document only (no neutral SubD exchange standard is targeted).                                      |
| Regulation         | None: direct edits are design operations with no certification meaning.                                                                                                                                                      |

## 10. Risks & assumptions

| Risk / assumption                                                                                                                                                     | Impact                                                 | Mitigation                                                                                                                                                                                                               |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A history step per drag grows the feature history fast                                                                                                                | Large documents, slow replay                           | Steps are small (ids + delta); COULD: squash consecutive edits of one entity on request (`squash_steps`, D7)                                                                                                             |
| Element ids drift when an earlier topology step is edited                                                                                                             | Later edits hit the wrong vertices                     | Persistent element ids minted step-scoped, recorded at first pick, `DIR_REF_LOST` instead of guessing (FR-DIR-20)                                                                                                        |
| Preview in the renderer has no OCC kernel (`docs/UI.md`)                                                                                                              | Face moves cannot preview locally                      | Backend `/preview` dry run on the native kernel, debounced; cage / pole previews stay local and per-frame                                                                                                                |
| Level-mesh vs limit volume differ by kernel (≈ 1.7 % on a cube)                                                                                                       | Agent reports two volumes for one part                 | `surfaceModel` in every result (FR-DIR-35)                                                                                                                                                                               |
| Catmull-Clark curvature is unbounded / zero at extraordinary vertices ("the curvature at the extraordinary vertex is in fact infinite" for the case Stam plots [R23]) | G2 checks fail near EVs                                | Report EVs separately; G1 option at EVs like Rhino [R5]; do not promise G2 there (G2 option COULD, with Rhino's bulge warning)                                                                                           |
| OCCT has no single "move arbitrary face" API                                                                                                                          | `move_faces` translate / rotate on curved faces is R&D | Offset via `BRepOffset_MakeOffset::SetOffsetOnFace` [R30], delete via `BRepAlgoAPI_Defeaturing` [R29]; translate / rotate built on defeature + re-intersection (TECHNICAL_SPEC §5.7); planar cases keep today's commands |
| Benchmarks we could not read (SolidWorks Instant3D, CATIA Imagine & Shape, Shapr3D)                                                                                   | Missed features                                        | Listed as not benchmarked; revisit when their help pages are reachable                                                                                                                                                   |
