# DIR — Validation pack

Proves a future implementation of [FUNCTIONAL_SPEC.md](../FUNCTIONAL_SPEC.md) / [TECHNICAL_SPEC.md](../TECHNICAL_SPEC.md).
"Validated" = every `VC-DIR-*` below passes in an automated gate: core cases in `npm run check` (no kernel), OCC cases in
`npm --prefix server test`, UI cases in the component / integration suites, the frame budget in the bench. Values and tolerances
live in [`expected_results.json`](expected_results.json) (authoritative); this page summarises them.

## 5. Notes on the data

- **Independent implementation, not llull's.** `ref_catmull_clark.mjs` re-implements the published rules; for sharpness 0 / ∞ they
  coincide with llull's code (same masks, same quad order, same fan triangulation), so VC-DIR-04..06 compare two implementations.
  A mismatch on first run is a finding to investigate, not a tolerance to widen.
- **Consistency checks inside the data.** Box seg [2,2,2] level 3 (6.31819142235) equals the cube with every edge at sharpness 1 at
  level 4 — one sharp step of the cube gives exactly the seg [2,2,2] box. The extrapolated limit volume of the cube (≈ 2.62042,
  observed convergence ratio 0.2499 ≈ 1/4 per level) is grade B.
- **Latency probe** (grade C): reference JS on one machine (`latency_probe.json` records Node version and CPU); the bench of
  TECHNICAL_SPEC §8 re-baselines the budget on llull's own code.
- **Curvature at EVs** is not tabulated: Catmull-Clark curvature is unbounded / degenerate there [S5]; `evaluate_subdivision` flags
  those samples instead.
