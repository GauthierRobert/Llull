## How sources were verified (read first)

- The `WebFetch` tool failed DNS resolution for every host in this session (`getaddrinfo ENOTFOUND`, including
  www.sae.org, www.iso.org, www.ecfr.gov and www.rfc-editor.org), and direct HTTPS from the sandbox was refused by the
  egress proxy (`CONNECT tunnel failed, response 403`) for every host except package registries (pypi.org,
  files.pythonhosted.org, registry.npmjs.org).
- External facts were therefore verified from **search-engine extracts of the named official pages** (WebSearch, standard
  and extended mode). Each row says what the extract showed. This is weaker than a full-page read. Facts that only
  secondary sources support are labelled **secondary** and are never used as normative requirements.
- **Cryptographic vectors were verified locally**, not from search extracts. The RFC 8032 Ed25519 TEST 1–3 vectors come from
  `cryptography_vectors-44.0.0-py2.py3-none-any.whl`, downloaded from PyPI (allowed host):
  size 36 831 897 bytes, sha256 `458ed682dbfa7144da156039c764ac707eb48b80e1d17ffe99e1de2edc91d5d7`. Lines 1–3 of its
  `asymmetric/Ed25519/sign.input` (sha256 `8db1fea94f4e78958aac6e839b483cdd79096d1fe478285f15164f9e58361baf`, 1024 lines,
  djb/SUPERCOP format) match RFC 8032 §7.1 TEST 1–3, and the search extract of the RFC confirms TEST 1's secret key.
  Python `cryptography` 50.0.1 and Node 22 `node:crypto` both re-derived and verified them (`generate_vectors.py`,
  `verify_vectors.mjs`). The wheel is Apache-2.0 / BSD licensed. It is **not stored** here (36.8 MB > 1 MB); only the
  three transcribed vectors are kept.
- Paywalled standards (EIA-649C, ISO 10007, AS9100D, AS9102C, DO-330, DO-254, ASME Y14.35, EN 9300): only the catalogue
  facts (title, edition, date, scope) are used. No clause text is reproduced or invented.
