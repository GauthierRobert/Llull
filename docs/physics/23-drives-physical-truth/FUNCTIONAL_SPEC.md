# PHY-23 DRV — Drives and physical truth: real motors, transmissions, friction, control and a verdict on every motion result — Functional specification

Status: specification only (2026-11-04). Nothing in this pack is built. Gap id `DRV`. Template:
[`../../aerospace/TEMPLATE.md`](../../aerospace/TEMPLATE.md); operator model: [`../../aerospace/AGENT_FIRST.md`](../../aerospace/AGENT_FIRST.md);
pack conventions: [`../README.md`](../README.md) §6. Owner request (2026-11-04): "add motors and enrich the motion part to create a
physical truth". Builds on PHY-10 RBD (rigid-body dynamics), PHY-21 FPR (functional prototype, as built) and feeds PHY-22 MOV
(motion video). Research: competitors, motor physics and benchmarks, [`validation/sources.md`](validation/sources.md).

## 1. Summary

llull simulates mechanisms with forces (`simulate_motion`, MuJoCo 3.16.0), but its actuators are idealised:

| #   | Limit (measured on main 00d5326f, 2026-11-04)                                                                                                                                             | Consequence                                                                                       |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1   | `add_motor` has two kinds: `torque_curve` (torque vs rpm table) and `speed` (a clamped servo); revolute joints only                                                                       | no electric motor: no voltage, current, back-EMF, rotor inertia, heat; no linear actuator         |
| 2   | the PHY-22 base plan drives its crank with `maxTorque: 1000000` N·m and nothing flags it                                                                                                  | an "infinite motor" (the classic SOLIDWORKS / Creo pitfall [R15][R26]) passes every check         |
| 3   | no controller, no position mode, no motion profile (trapezoid, S-curve, cam law); PHY-10 FR-RBD-09 is spec only                                                                           | no indexing table, pick-and-place axis or servo axis can be modelled                              |
| 4   | gears: one constant efficiency, smoothed by speed sign (`gearLoss.ts`); no back-drive efficiency, no self-locking, no backlash; no screw, belt or rack                                    | worm and lead-screw holding, lost motion and screw drives are wrong or impossible                 |
| 5   | joint friction = MuJoCo `frictionloss` (one Coulomb level) + viscous `damping`; no stiction, Stribeck or load-dependent μ·F·r                                                             | stick-slip, breakaway and bearing losses that grow with load are missing                          |
| 6   | no joint limits or end stops in the dynamics (MuJoCo model has no `range`)                                                                                                                | a slider can run through its stop; no impact load                                                 |
| 7   | trust signals exist but are scattered: energy balance, loop residual, `check_timestep_convergence` (engine plans), `check_dynamics`; nothing says "this result is true to ±x %, because…" | the agent cannot prove a motion result, the owner cannot tell a plausible picture from a true one |

This pack adds **real actuators** (DC motor from a datasheet first, then PMSM / BLDC, stepper, induction), **drives** (voltage,
torque, velocity, position with tuned cascade control, prescribed motion), **motion profiles**, **lossy transmissions** (gears with
direction-dependent efficiency and backlash, belts, lead / ball screws, rack and pinion), **joint physics** (stiction, Stribeck,
load-dependent friction, end stops), **time-varying loads**, a **drive sizing report**, and a **physical-truth verdict**
(`check_motion_truth`) that states, with evidence, how far a motion result can be trusted.

## 2. Context and value

- **Who needs it.** Machine builders sizing a motor and gearhead for an axis; robotics (arm joints, grippers); automation
  (indexing tables, conveyors, lifts with lead screws); product design (doors, lids, recliners, actuated hinges); education;
  and the agent itself, which must answer "will this motor do it, and how sure are you?".
- **How incumbent tools do it** (detail and grades in [`validation/sources.md`](validation/sources.md)):
  - CAD motion add-ons drive joints **kinematically**. In SOLIDWORKS Motion a motor's motion "supersedes" the other elements and a resisting load
    "increases the power consumption of the motor, but does not slow down the motor motion" [R15]. Creo servo motors impose position, velocity or acceleration
    from profile functions (constant, ramp, cosine, cycloidal, SCCA, parabolic, polynomial, table); force motors need the dynamics
    option; sizing is "graph the load reaction at the servo" [R10][R11]. Neither has an electrical motor model or a torque–speed
    limit (not found).
  - Multibody solvers add physics. Adams Machinery has belts, chains, bearings, gears and a motor module [R19]. MotionSolve has
    a LuGre-type joint friction with Stribeck, load sources (preload, reaction, bending, torsion) and pin geometry [R12]. Chrono has
    position / speed / torque motors and 1D shaft drivelines [R13]. Drake has an effort limit (default infinite), rotor inertia and
    gear ratio with reflected inertia ρ²·I_r [R14].
  - System simulators model the motor. Simscape DC Motor takes R, L, kt or stall / no-load data, with a thermal port and a
    "derived data sheet" [R5]. Modelica `LossyGear` picks the mesh efficiency by power-flow direction with an explicit stuck state;
    `Gearbox` adds elasto-backlash; `BearingFriction` warns that regularised friction is stiff [R7][R8][R9].
  - MuJoCo, llull's engine, ships a `dcmotor` actuator (voltage, resistance, inductance, thermal, cogging, LuGre, controller attributes)
    [R2][R4]. The string is present in llull's pinned 3.16.0 WASM build [M1].
- **What nobody offers in one place, and llull will** (llull's laws make it cheap):
  1. A datasheet motor whose data is **checked for internal consistency** before use (stall torque = kt·U/R, no-load speed, τm).
  2. Physical limits on every actuator, with **provenance** (source, grade) flowing into the result.
  3. An **energy ledger per element** that closes.
  4. A **verdict with evidence**: time-step convergence with an error band, constraint softness, effort bounds, provenance, and
     (V1) a second, independent engine.
  5. All of it is drivable from the CLI and reproducible (deterministic).
     Users' top complaints are redundant constraints, torque explosions, friction that disagrees with hand calculations, and
     motors that ignore their load [R16][R26][R27][R15]. Each one maps to a check in this pack.

## 3. Personas and user stories

| Persona              | Story                                                                                                                                                                                                                                              |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CLI agent (operator) | I enter a maxon motor from its datasheet; `check_motor_data` tells me the sheet is self-consistent to 0.5 %; I drive the axis with an S-curve; `size_drive` says the RMS torque uses 62 % of the continuous rating and the winding peaks at 96 °C. |
| CLI agent            | Before I report a result I run `check_motion_truth`; it says `trusted`, the time-step error is below 0.3 %, the energy ledger closes to 1e-5, and every parameter has a source. I quote that.                                                      |

| Reviewer (engineer)  | I open the energy ledger and the torque–speed chart with the operating points and the motor envelope, and I sign the sizing.                                                                                                                       |

## 6. Workflows

**CLI (primary).**

```bash
llull run validation/plans/drv_servo_sizing.plan.json --doc axis.llull.json     # motor, gear, profile, drive
llull check_motor_data motor=m_re40 --doc axis.llull.json                         # 6 checks, derived vs datasheet
llull evaluate_motion_profile profile=p_index samples=201 --doc axis.llull.json   # peaks of v, a, jerk
llull size_drive motor=m_re40 duration=5 margin=0.2 ratioSweep='[5,8,10,12,15,20]' --doc axis.llull.json
llull check_motion_truth level=full --doc axis.llull.json                        # verdict + evidence
llull plot_simulation quantities='["operating_points","winding_temperature"]' --doc axis.llull.json --save sizing.svg
llull render_animation source='{"kind":"simulation","duration":1}' overlays='{"readouts":["m_re40.current","m_re40.torque"]}' --save axis.mp4   # PHY-22
```

An agent's report quotes the `check_motion_truth` verdict and its accuracy statement, never just the numbers.

**Desktop UI (review surface).** Mechanisms › Physics › Drives: list of motors and transmissions; the motor editor shows the
consistency checks live; the profile editor plots p / v / a / j; after a run, the torque–speed chart shows the motor envelope and
the operating points, coloured by time; the thermal chart shows the winding temperature against its limit; the energy ledger
shows bars per element; a truth badge (trusted / plausible / not trusted) opens the evidence list. All edits dispatch commands.

## 8. Standards alignment

- IEC 60034-1 (rotating electrical machines, rating and performance) defines duty types S1–S10 [R31, catalogue only]. llull names
  the duty type a cycle resembles (S1 continuous, S3 intermittent periodic, S6 continuous operation with intermittent load) for
  information only and never claims conformity.
- VDI 2143 (cam motion laws) [R32, catalogue only]: llull uses the law names and checks their coefficients analytically
  (VC-DRV-22); clause content is not reproduced.
- PHY-00 V&V vocabulary (verification vs validation, GCI) for `check_motion_truth`.

## 10. Risks and assumptions

| Risk                                                                                                                             | Mitigation                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Stiff electrical dynamics (τe = 0.29 ms) against a 1 ms physics step                                                             | exact exponential update of the current per step (TR-DRV-06); warn `DRV_ELECTRICAL_STIFF` when τe < Δt and fall back to quasi-static |
| MuJoCo soft constraints make "physical truth" a matter of tolerance [R3]                                                         | softness is measured and reported (loop residual, penetration) and enters the verdict                                                |
| Stiction chatter at zero velocity (Modelica warns [R9])                                                                          | friction stays a MuJoCo constraint (box bound), its level scheduled per step; no regularised sign function                           |
| A load-dependent friction level computed from the previous step's reaction lags by one step                                      | documented; `check_motion_truth` Δt/2 run measures it; VC-DRV-19 tolerance 1 %                                                       |
| Model-form error: a 2-node thermal network does not reproduce both datasheet time constants (36.6 s / 916.5 s vs 41.5 s / 809 s) | stated in every thermal result as an accuracy note; the steady-state temperature (the sizing limit) is exact for the model           |
| Datasheets are rounded to 3 digits                                                                                               | consistency tolerance 2 %; VC tolerances ≥ 0.5 %                                                                                     |
| Two mechanism models (`doc.joints` kinematic vs `doc.dynamics`) stay separate (PHY-21 Q2)                                        | this pack only extends `doc.dynamics`; profiles are shared data usable by both                                                       |
