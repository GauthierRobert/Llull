# 09 COM — Commercial and support readiness (local-only) — Functional specification

Status: specification only (2026-10-28). Nothing in this pack is built. Gap id `COM`. Template:
[`../../aerospace/TEMPLATE.md`](../../aerospace/TEMPLATE.md), grades as in [`../../plant/TEMPLATE.md`](../../plant/TEMPLATE.md),
track rules in [`../README.md`](../README.md). Operator: a professional engineer at the desktop app, and the office's IT
administrator for licences and installs; every capability also has a CLI path (agent-first, AF-11 / AF-41).

> **Not legal advice.** This pack quotes regulation text and lists the obligations it appears to create. Every statement of the
> form "applies to llull" or "llull must" that depends on how a law is interpreted is marked **[counsel]** and repeated in §11
> as a question for the owner and legal counsel. Nothing here is a legal conclusion.

## 1. Summary

An engineering office cannot adopt llull as a daily tool today, whatever its features, because the product around it does not
exist:

| Need of the office                                                      | Today (evidence)                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Buy it and prove it is licensed, on PCs that may never see the internet | No licence. LC1 step 3 removed the offline licence (`server/src/license.ts`: Ed25519-signed `{customer, seats, expires, features}`, evaluation fallback of 3 users) together with named users, audit trail and `/admin`, because they belonged to the multi-user cloud host ([`../../decisions/LC1-local-only.md`](../../decisions/LC1-local-only.md)). No `LICENSE` file, no `license` field in `package.json` (`"private": true`, version `0.1.0`) |
| Know what a release changes and how long it is supported                | No release, versioning, deprecation or support-period policy; document format v3 reads v1–v2, but the owner's working rule is "no backward compatibility until told otherwise" (memory, 2026-10-22)                                                                                                                                                                                                                                                  |
| Get help when something breaks                                          | Crash reports exist and stay local (`server/src/crashReports.ts`, `llull crashes`); the in-app `ReportIssueDialog` drafts a reviewed GitHub issue (title, body, reproducer plan; nothing sent automatically). No support channel, no SLA, no security contact, no vulnerability disclosure policy                                                                                                                                                    |
| Learn the tool                                                          | `llull guide` (conventions), `llull describe` (one command's schema), `ShortcutsDialog` (keyboard sheet), 23 developer-oriented `docs/*.md`. No user manual, no in-app help, no tutorials outside [`../../PILOT.md`](../../PILOT.md)                                                                                                                                                                                                                 |
| Use it in French, Dutch or German, with decimal commas                  | English only. No i18n library; `toLocaleString('en-US', …)` hard-coded in `TimelineDock.tsx` and `PhysicsSection.tsx`; ≥ 615 literal UI strings in 240 `.tsx` files (§9 of the validation plan, measured by regex, a lower bound)                                                                                                                                                                                                                    |
| Meet its own legal duties when buying software in the EU                | No EULA, no warranty disclaimer for engineering results, no privacy notice, no SBOM, no CE / CRA technical file, no accessibility statement                                                                                                                                                                                                                                                                                                          |

This pack specifies what has to exist so that an office can **license llull offline, read its help in its own language, get
support, and meet its legal duties** — readiness level PRL 4 "Adoptable" ([`../VALIDATION.md`](../VALIDATION.md)) — without
breaking the product directive: local-only, offline, no cloud, no phoning home.

The common pattern for offline engineering software is a **signed licence file bound to a machine or to a LAN licence server,
moved by file exchange, with a server-side or file-side expiry and a borrow mechanism for laptops**. The removed `license.ts`
already had the core of it (Ed25519 over a JSON payload, verified with `node:crypto`), and the PLM pack ships Ed25519 primitives
and a key-trust flow in the host layer (`server/src/plm/ed25519.ts`, `desktop/src/keyTrust.ts`).

### 2.3 Why llull must close the gap

- The production gate shows llull can do the work ([`../../PRODUCTION_GATE.md`](../../PRODUCTION_GATE.md)); an office still
  cannot **buy** it (no licence), **trust its future** (no support period or compatibility promise), **get help** (no support
  path), **read it** (English-only, no manual) or **meet procurement and legal checks** (no EULA, SBOM, CVD, CRA file).
- The CRA's reporting duty already applies (11 Sept 2026) to any product in scope that is on the market; whether llull is "on
  the market" today, as a `private` 0.1.0 with a GitHub repository, is a **[counsel]** question (§11 Q3). The PLD applies to
  products placed on the market after 9 Dec 2026. The first commercial sale must therefore be preceded by M1 (§10 of the
  technical spec).

## 3. Personas and user stories

- **Engineer (daily user, desktop).**
  - US-1 "On my office PC, which has no internet, llull starts licensed and never asks to go online."
  - US-2 "If something is wrong with the licence I can still open, save, export and print my drawings; I am never locked out of my own work."
  - US-3 "The UI, the help and the error messages are in French (or Dutch, or German); numbers use a decimal comma; the files I send stay readable by anyone."
  - US-4 "I press F1 on a tool and read what it does, its parameters and an example, offline."
  - US-5 "When llull fails I build a support bundle, see every file in it, remove what I don't want to send, and send it myself."
- **IT administrator.**
  - US-6 "I activate 10 seats by file exchange, move a seat to a new PC, and run a floating licence server on our LAN for laptops."
  - US-7 "I know the support end date of the version we run, I get signed updates that I can deploy from a network share, and I have an SBOM for our security review."
- **Office manager / buyer.**
  - US-8 "I read the EULA, the warranty and liability terms and the privacy notice in my language before buying; I know what support tier I pay for and its response times."
- **Security researcher.** US-9 "I find the security contact and the disclosure policy in one place and get an acknowledgement."
- **Owner (vendor).** US-10 "I know which EU duties apply to me, with dates, and I have a runbook for a 24-hour CRA early warning."
- **Agent (CLI).** US-11 "`llull license status --json`, `llull diagnostics create --json`, `llull version --json` give me stable fields and codes; JSON output is never translated."

## 6. Workflows

**CLI (admin and agent).**

```text
llull license request --out seat-req.json                # FR-01: request file (fingerprint hash, product, version)
#   … on a connected machine, the vendor portal or the vendor's offline tool returns licence.llic …

llull diagnostics create --out bundle.zip --json         # FR-17: manifest listed; --include-document to add the open document
llull diagnostics show bundle.zip                        # every item and its redactions, before sending
llull help draw_polyline [--lang fr]                     # FR-22/28: generated reference page (describe stays the JSON schema)
llull reset --all --yes                                  # FR-36
```

preview, checkboxes, Save) · Help › Contents (F1) · Settings › Language and formats · Help › About (version, support end date,
EULA, third-party notices, security contact, data removal).

**Vendor (owner).** Licence issuance tool (offline-capable, keys on a token, never in the repo); release pipeline
(`release:check` → sign → SBOM → notes); CVD inbox + triage; CRA runbook.

## 10. Risks and assumptions

- **Offline licensing cannot stop a determined attacker** who patches the client [R5]; the aim is honest-customer compliance and
  tamper evidence, not DRM. No obfuscation that would hurt support or reproducibility.
- **Read-only fallback** (FR-03) means an unlicensed copy remains a free viewer / exporter. Accepted as the price of never holding
  data hostage (owner decision, §11 Q1).
- **CRA automatic updates vs offline** (Annex I Part I (2)(c) "where applicable … enabled as a default setting … opt-out"): an
  update check that is on by default would contact a server, against the "no network needed" directive. Spec: offline-safe update
  sources and a visible opt-in / opt-out; the default is a **[counsel]** + owner question (§11 Q6).
- **Compatibility promise vs the owner's "no backward compatibility" working rule**: the promise starts at 1.0.0 only; until then
  the working rule stands (§11 Q4).
- **Open-source option**: open-sourcing the core does not remove CRA manufacturer duties once llull is monetised (recital 18,
  Commission page [R12]) and does not remove PLD exposure for a commercial supply (Art 2(2)) **[counsel]**.
- **Translation cost** for 865 command descriptions × 3 languages; the UI chrome comes first, the reference falls back to English
  with a marker (FR-29 is SHOULD).
