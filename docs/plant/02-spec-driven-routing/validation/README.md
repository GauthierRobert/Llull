# Gap 02 RTE — Validation pack

This pack proves that llull's spec-driven routing builds the right pipe: the right fittings, in the right number,
with the right cut lengths, connected to the right ports, and that it refuses or flags what a piping designer
would refuse or flag. Every reference value is (a) quoted from a source in [sources.md](sources.md) (grade A
gates, B / C do not), (b) derived from a cited closed form with the derivation shown below, or (c) marked
`TBD — measure with <tool>`. **No expected value was produced by running llull** (nothing of this gap is built).

How the cases run once the MVP lands (TECHNICAL_SPEC §9):

- Unit tests read `data/*.json` directly.
- `tests/unit/plant/piping/rteScenarioPlans.test.ts` runs the `plans/*.json` through `build_project` (the path of
  `llull run plan.json --json`) after importing `data/catalog_stub_cs150.json` and `data/spec_cs150.json` (01 PSC formats; the plans inline both as `harness.inline`), then
  compares each `expected` row (`path`, `value`, `abs` / `rel`). Plans with `cases` run each case as its own plan.
- The production-gate agent driver runs the same plans unattended (AF-23).

## Gate policy

- Gates: grade A rows and closed forms. The spec stub's numbers are **inputs**: every cut length is derived from
  the stub value the plan loads (e.g. gasket 3.0 mm, grade C as a standard value, is a declared input, not a
  claim about B16.21). Rows whose standard value is grade A (90 LR A, tee C / M, gate valve F-F) are also checked
  against the stub by `catalogueConsistency.test.ts` so the stub cannot drift from the published tables.
- Project rules (weld spacing, handwheel height, insulation thickness table, branch table) are **named defaults or
  explicit params**; their numbers never gate a claim about a standard.
- PCF output is not gated here (no openly licensed sample was reachable); 05-isometrics-fabrication owns it.

- **D27 (orphan supports, VC-RTE-45; V1c).** A rule, not a number: three supports placed on a run by spacing 3000 on a 6000 mm run over beams at 500 / 3000 / 5500 are three; when their run is gone, loading the file keeps all three and `check_pipe_supports` returns `orphans.length` 3, `totals.orphans` 3, `pipes` empty, `ok` false, each with the code `RTE_SUPPORT_ORPHAN`; the live document gives the same data.
- **D28 (obstacles from the run model, SC-RTE-24, VC-RTE-46; V2).** Header DN150 (OD 168.3, half 84.15), spec insulation H 60 mm at 180 degC, z 3000; new DN100 line (OD 114.3, half 57.15), clearance 150. The header body for the new pipe is its envelope: clearance needed from the header axis = 84.15 + 60 + 57.15 + 150 = 351.3 mm. Lattice 50 mm from the port height 3000: 3350 is 350 (short by 1.3), 3400 is 400. The jog legs must also be at least 2 x 152 = 304 -> 7 cells = 350 mm: 400 satisfies it. Length = 6000 (y from -3000 to 3000) + 2 x 400 = 6800; 4 bends (a jog is 2 bends each way; going round the header end is 5000 mm away). Bare header: 84.15 + 57.15 + 150 = 291.3 -> 350, length 6700. Over and under cost the same; the search order takes the lower z (2600) first.
- **D29 (several lines, SC-RTE-25, VC-RTE-47; V2).** Wall across x 5000 (boxes 4950..5050), y and z within +-1000, hole y,z within +-200 (400 x 400). A DN100 pipe in the hole reaches 57.15 + 50 = 107.15 mm each side, so the hole holds exactly one pipe (the free centreline region is +-92.85 mm, one lattice point at 200 mm). Y: ports (1000,0,400) and (9000,0,400), 8000 apart, down 400 to the hole axis and up 400 again: 8000 + 2 x 400 = 8800; a grid box margin of 400 around the ports keeps its z within 0..800 and y within +-400 (the wall edge at 1000 + 107.15 is out of reach, so Y cannot go round). X: ports (0,0,0) and (10000,0,0), margin 1600; with Y in the hole it goes round the wall edge: 1000 + 107.15 = 1107.15 -> 1200 on the 200 mm lattice, up 1200 and down 1200: 10000 + 2 x 1200 = 12400. Both are DN100: the order is by distance (X 10000, Y 8000): X, Y; X fills the hole, Y fails (no path), Y is promoted, the second pass is Y, X.
- **D30 (first-move candidates, VC-RTE-48; V2).** SC-RTE-08 ports with a U-shaped keep-out around the straight +X path (back wall at x 2000, side walls at y +-1450, open toward the port). Lattice cost = (6000 - 2 x 200 stubs) Manhattan = 5600 mm plus 3 bends x 1000 = 8600 mm = 8,600,000 um for a route that leaves the pocket sideways (+Y first) and for the +X first move that escapes over the top; both cost the same, the tie goes to the lower first-move axis index (+X = 0, +Y = 2). With a budget of 500 expansions per candidate the +X candidate (984 expansions needed) stops with a lower bound below the cost, so +Y wins and `optimal` is false. The expansion counts 984 and 104 are regression values of the algorithm, not hand numbers.
- **D31 (edits after an auto-route, VC-RTE-49; V2).** A rule: `autoRoute` present means the PIs are exactly the validated solution. A hand edit or a stretch changes the PIs, so the record is dropped; a valve in a leg, a support, a save and load do not.

All derivations were recomputed with a scratch script (closed forms only; no llull code).

## Known limits of this pack

- No PCF / IDF sample could be downloaded (see sources.md "Not verified"); the hand-off is a 05 ISO VC. The V1 part 2 PCF follows the conventions of 05 `iso-01-L101-dn100.pcf` and its `skey_catalogue.json` (only ELBW, ELSW, TEBW, FLWN, REBW are written); the BOLT record carries no attributes besides ERECTION-ITEM and ITEM-CODE (the keyword names of bolt diameter and length are not confirmed), `SPINDLE-DIRECTION` and `UNIQUE-COMPONENT-IDENTIFIER` are grade B. The golden files are hand-checked against the stub dimensions, not against a third-party reader.
- V1 part 2: IFC is written as IFC4 (the existing `export_ifc` schema; IfcDistributionPort, IfcRelNests, IfcRelConnectsPorts and IfcValve are IFC4 entities), not 4.3. The exact STEP path is tested with a scripted kernel and, since V1c, measured against the native OCCT kernel (D24: volumes within 1e-6 relative of the closed forms). Heat loss is a screening figure (no radiation, no temperature-dependent conductivity).
- The weldolet outlet (144 mm from the header centreline) is a declared stub input, not a sourced MSS SP-97 value; the SC-RTE-03 DN50 cut 856 is derived from it. The reducer length 140 is grade B.
- The WN flange Y values differ by 1.3-1.6 mm between sources (raised face included or not); they are stub
  inputs, not gates.
- The beam-axis convention of SC-RTE-07 was confirmed against `add_steel_member` (02 M3): clash depth 24.45 mm. The clash bodies are circumscribing square boxes of the round pipe, since V1 part 1 also of valves, flange plates / hubs, tees, olets, reducers and valve operators (a valve body is the pipe OD unless the row has `bodyDiameter`).
- V1 part 1 inputs (small-bore catalogue, operator valves, eccentric reducer rows) are declared stub numbers shaped after B16.11 / B16.34 / B16.5 / MSS SP-97; the socket gap 1.6 mm is grade B (`flanged_components.json`). The bundled `llull-open-piping` has no SW, threaded or eccentric rows: those specs run only on these stubs until 01 PSC adds sourced rows.
- Handwheel height, insulation thickness and branch-table cells are project data with no public standard value.
